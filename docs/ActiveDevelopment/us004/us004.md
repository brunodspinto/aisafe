# US004 - Continuous Integration Server

## 1. Contexto
Esta tarefa foi atribuída no Sprint 1 e estabelece as fundações para o controlo de qualidade do código do projeto AlSafe. É a primeira vez que está a ser desenvolvida e o seu objetivo é garantir que todas as alterações submetidas pela equipa mantêm o sistema num estado compilável e funcional desde o primeiro dia.

## 2. Requisitos
**US004:** As Project Manager, I want the team to setup a continuous integration server. GitHub Actions/Workflows should be used.

Adicionalmente, esta US dá resposta direta às seguintes restrições não funcionais (NFRs) estipuladas para o projeto:
* **NFR05:** The Github repository will provide night builds with publishing of results and metrics. The project will
  use Maven as build automation tool.

## 3. Análise
Para dar resposta a esta necessidade, a equipa optou por utilizar o **GitHub Actions**.

A configuração deste sistema obriga à criação de um *workflow* automatizado que garanta os seguintes comportamentos:
1. Reagir a eventos de `push` e `pull_request` direcionados às *branches* principais (`main` ou `master`).
2. Executar autonomamente uma vez por dia (durante a madrugada) para cumprir estritamente a diretriz das *night builds*.
3. Preparar o ambiente de execução nas máquinas da cloud com o Java Development Kit (JDK) 21.
4. Invocar o motor Maven para limpar compilações anteriores, recompilar todo o código e executar a totalidade da *suite* de testes (`mvn clean verify`).

## 4. Design
A arquitetura da solução baseia-se na declaração da infraestrutura como código (IaC) através de um ficheiro de configuração YAML. O GitHub exige que este ficheiro seja colocado numa diretoria oculta e específica: `.github/workflows/`, localizada obrigatoriamente na raiz do repositório.

O schedule para as *night builds* utilizará a expressão cron `0 2 * * *`, ordenando aos servidores do GitHub que corram o *script* todos os dias às 02:00 da manhã.

## 5. Implementação
Para concretizar a integração, foi criado o ficheiro `.github/workflows/maven-ci.yml` na raiz do projeto com o seguinte código:

```yaml
name: AlSafe CI Build

on:
  push:
    branches: [ "master", "main" ]
  pull_request:
    branches: [ "master", "main" ]
  schedule:
    - cron: '0 2 * * *'

jobs:
  build:
    name: Build and Test
    runs-on: ubuntu-latest

    steps:
    - name: Checkout Code
      uses: actions/checkout@v4

    - name: Set up JDK 21
      uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: 'temurin'
        cache: maven

    - name: Build and Run Tests with Maven
      run: mvn -B clean verify --file eapli.base/pom.xml
